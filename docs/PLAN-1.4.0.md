# 1.4.0 Implementation Plan / 实施计划

Status: implementation branch `release/1.4.0`  
Release principle: preserve the current installed DST `haptics.lua` as the event source of truth; add no input-button rumble and no speculative gameplay hooks.

## Goals / 目标

1. Correct listener-local events emitted through `TheFrontEnd` or `TheFocalPoint`.
2. Preserve `PlaySoundWithParams` and named-loop `SetParameter` data.
3. Use the actual audio listener position for three-dimensional attenuation.
4. Separate native category scaling from semantic tool/combat scaling.
5. Reduce generic hurt double feedback without inventing damage semantics.
6. Make loop recognition, wrapper health, diagnostics and update audits more testable.
7. Produce a clean client-only Steam Workshop package without Klei source or raw waveform assets.

## Fidelity boundaries

- `TheInputProxy:AddVibration` cannot play Klei WAV samples directly. Asset envelopes remain down-sampled approximations.
- Lua exposes no FMOD audible-state or attenuation getter. Listener-distance curves remain documented approximations.
- Lua cannot determine whether a motor physically moved. Xbox/DS4/DualSense acceptance needs real hardware.
- Server-only events without a replicated client proof remain conditional; 1.4.0 will not infer them from buttons or animations.
- `audio_intensity` remains indexed and logged but does not scale the motor until its native haptic meaning is proven.

## Test gates

1. Parse every distributable Lua file using DST-compatible Lua 5.1.
2. Profile all current native definitions with no missing event.
3. Pass adapter, action bridge and runtime settings tests.
4. Add parameter, local-context, 3D listener, combined scaling, hurt arbitration and loop lifecycle tests.
5. Load the installed package through the DST frontend with no Lua error.
6. Verify Profile OFF, Compatibility/Native/Diagnostic modes, pause, disconnect and world unload.
7. Record physical acceptance separately for Xbox, DS4 and DualSense over each available USB/Bluetooth/Steam Input route.

## Steam Workshop packaging

- Package root contains `modinfo.lua`, `modmain.lua`, `scripts/`, `modicon.xml`/`modicon.tex` when generated by Klei tools, `LICENSE`, and user documentation.
- Keep `client_only_mod = true`, `all_clients_require_mod = false`, `server_only_mod = false`.
- Exclude tests, audit tools, Git metadata, build output, Klei scripts, raw Haptic WAVs, logs and local paths from the Workshop content folder.
- Validate title, bilingual description, semantic version, preview asset, `client_only_mod` and `utility` tags before upload.
- Upload/update only through the DST/Klei Workshop uploader or an authenticated Steam UGC workflow. Publishing requires the owner's Steam session and acceptance of the Steam Workshop legal agreement.

## Release sequence

1. Implement and commit on `release/1.4.0`.
2. Push the branch to `origin` after each verified milestone.
3. Build the clean Workshop staging folder and release ZIP.
4. Install the same staged files into local `mods/dst_haptics_compat` and run frontend validation.
5. Merge fast-forward to `main`, tag `v1.4.0`, and push branch/main/tag.
6. Upload the staged content with the owner's Steam account; use the 1.4.0 changelog as the Workshop change note.
