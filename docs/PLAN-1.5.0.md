# 1.5.0 开发与验收计划

## 目标与基准

以当前游戏 haptics.lua 的事件、触发条件、player_only、category 和相对强度为依据。100% 表示未经用户倍率修改的原版兼容基准；公开 Lua API 无法证明与闭源原生输出的绝对强度、采样时长完全相等，不以未测量的数值冒充原版。所有已知以及未来新增的事件均应进入可调节类型；不匹配专门类型时使用原版 category 和通用回退。

## 要求一：完整调节与手柄适配

- 总体和各类型提供强度、时长两个独立轴，0%–200%，步长 5%，默认 100%。保留现有设置名以兼容已保存配置。
- 类型覆盖工具、战斗、危险、玩家交互、Boss、环境、UI 和持续循环；同一事件的原版分类与语义类型组合规则需在配置说明中明确。
- 时长缩放覆盖包络延迟和脉冲宽度，保持节奏比例；0% 不输出、不产生零延迟任务。循环调节单次脉冲宽度，声音停止/实体移除仍立即结束。
- 提供默认开启的设备适配开关，关闭后使用通用输出。Xbox、DS4、DS5 的多层包络使用统一原版事件输入，专门响应转换保持强度单调，避免削平低强度层次。
- 不宣称 Legacy Rumble API 提供 DualSense 自适应扳机或原生高频触觉。真实 USB/Bluetooth 与 Steam Input 验收记录设备和证据。
- 测试全部 41 档、0/100/200 边界、分类回退、取消/暂停/断开、具名循环、设置即时更新以及三种设备路由。
- 完成后提交代码、测试和本要求 note，立即推送 release/1.5.0。

## 要求二：结构、兼容与性能

- 统一启动和局内配置读取，集中校验比例，处理无效值与旧配置迁移。
- 缓存按 event 生成的不变 profile，普通声音 O(1) 旁路，避免每次命中重新创建包络。
- 审核声音 wrapper 参数/返回值、其它 Mod 链接、重复安装、原生抑制与恢复。
- 审核调度取消、循环混音、生命周期、缓存有界性及热插拔，修复发现的问题并加入有意义的行为测试。
- 比较普通声音与匹配事件的热点耗时和任务数，记录测量环境与限制。
- 审查打包路径、版本来源、文档链接和 CI，避免发布过程版本漂移。
- 完成后提交审核 note 与性能证据，立即推送。

## 要求三：文档与图标

- README.md 全中文；README.en.md 独立英文。内容重写为安装、工作原理、设置、设备支持、限制、问题排查和开发入口。
- 绘制简约线条手柄/触觉图标，使用原创几何结构和留白；不使用 Apple 标识或现有产品图标。
- 保留可编辑图标源，生成 Workshop 预览和游戏内可用图标，实际查看渲染结果并校验打包引用。
- 完成后提交文档/图标 note，立即推送。

## 发布门槛

Lua 5.1 语法和行为测试通过；全部本机原版定义覆盖；远端 CI 通过；安装文件与发布内容一致；真实运行/硬件未验收项目明确记录。完成审计后合并 main、创建 v1.5.0 并检查远端 release 资产。每个要求完成时分别提交，不能以最终一次提交代替逐要求同步。
